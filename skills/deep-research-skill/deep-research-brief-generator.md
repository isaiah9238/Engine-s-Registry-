# Deep Research Prompt & Brief Generator

## Overview & Mission

The `deep-research-brief-generator` skill transforms unstructured or ambiguous research requests into standardized, machine-executable **Research Briefs**. When passed to deep research systems (such as OpenAI Deep Research, Gemini Deep Research, or open-source multi-agent frameworks like `open-deep-research-pipeline`), these structured prompts eliminate context clash, prevent token inflation, and force rigorous source-grounded verification.

---

## The Deep Research Prompt Template Schema

Every prompt generated by this skill follows a strict 5-part anatomical structure:

```markdown
### 1. CORE OBJECTIVE
[Define the primary research question or goal in 1–2 crisp sentences.]

### 2. RESEARCH SCOPE & SUB-TOPICS
Investigate the following specific dimensions:
• Sub-topic A: [Core concept, mechanism, or technical foundation]
• Sub-topic B: [Comparative analysis, competing architectures, or alternative approaches]
• Sub-topic C: [Quantitative metrics, benchmarks, financial statistics, or timelines]
• Sub-topic D: [Constraints, risks, edge cases, or trade-offs]

### 3. SOURCE CONSTRAINTS & PROVENANCE
• Primary Targets: [e.g., Peer-reviewed journals (arXiv, IEEE), SEC filings, official docs, GitHub]
• Excluded Sources: [e.g., Unverified blogs, promotional press releases, paywalled summaries]
• Verification Gate: Cross-reference facts across at least 2 independent sources before treating as verified.

### 4. DESIRED REPORT FORMAT
• Executive Summary: High-level synthesis (3–4 bullet points).
• Deep-Dive Sections: Structured analysis organized by sub-topic.
• Comparative Matrix: Structured Markdown table comparing key variables or metrics.
• Source Provenance Table: URL, publication, and access date for all referenced materials.

### 5. CITATION & FACTUAL DISCIPLINE
• Attach inline citations ([Source Name, Year]) to every claim, metric, and date.
• Explicitly state any gaps or source contradictions rather than estimating or making assumptions.
```

## Step-by-Step Prompt Assembly Workflow

### Phase 1: Ambiguity Assessment & Intent Triage
1. Analyze the user's raw query across three core dimensions: **Scope**, **Depth**, and **Constraints**.
2. If the prompt contains high ambiguity, resolve key unknowns before assembling the final brief.
3. Identify domain-specific keywords and authoritative venues (e.g., `site:arxiv.org`, `site:gov`, `NIST`).

### Phase 2: Sub-Topic Breakdown (Parallelization Mapping)
1. Deconstruct the primary objective into **3 to 5 independent sub-questions**.
2. Ensure sub-topics have minimal overlap so execution sub-agents can research in isolated context windows without duplicating web requests.

### Phase 3: Constraint & Verification Definition
1. Establish mandatory source categories (e.g., primary technical documentation vs. industry analyst reports).
2. Set explicit exclusion rules to prevent toxic web clutter or SEO spam from entering the RAG context.
3. Enforce a **Verification Threshold** (e.g., minimum 2 independent sources per critical metric).

### Phase 4: Output Schema & Citation Rule Injection
1. Specify exact formatting requirements (Executive Summary, Comparative Table, Deep Dives).
2. Append hard negative constraints: *"Never fill missing facts with ungrounded assumptions; report information gaps explicitly."*

## Examples & Reference Walkthroughs

### Example 1: Hardware Benchmarks (Quantum Computing)

```markdown
### CORE OBJECTIVE
Evaluate 2025–2026 performance benchmarks comparing neutral-atom quantum computing architectures against superconducting qubit systems.

### RESEARCH SCOPE & SUB-TOPICS
1. Physical vs. Logical Qubits: Ratios and error-correction overhead (surface codes vs. color codes).
2. Gate Fidelity & Coherence: Two-qubit gate fidelities (≥99.5% threshold) and T1/T2 coherence times.
3. Algorithmic Benchmarking: Published Quantum Volume and Q-Score results.
4. Commercial Roadmaps: Milestone timelines for IBM Quantum, QuEra Computing, and Quantinuum.

### SOURCE CONSTRAINTS & PROVENANCE
• Primary Targets: PRX Quantum, Nature Physics, IEEE Micro, official hardware whitepapers.
• Exclusions: Non-technical news summaries, investor pitch decks.
• Verification: Cross-reference gate fidelity figures with published benchmark papers.

### DESIRED REPORT FORMAT
• Executive Summary (3 bullets)
• Hardware Architecture Comparison
• Technical Benchmark Comparison Table (Qubit count, Gate Fidelity, T1 time)
• Source Provenance Table

### CITATION & FACTUAL DISCIPLINE
• Inline bracketed citations [Paper/Lab, Year] for all performance metrics.
• Report unverified roadmap projections explicitly as "Vendor Claims."
```

### Example 2: Cybersecurity & Agent Vulnerabilities

```markdown
### CORE OBJECTIVE
Analyze the threat taxonomy and mitigation strategies for prompt injection and privilege escalation in autonomous agent skills.

### RESEARCH SCOPE & SUB-TOPICS
1. Indirect Prompt Injection: Attack vectors via untrusted web content and document ingestion.
2. The Consent Gap: Disconnect between user-approved scope and unconstrained host script execution.
3. Empirical Security Statistics: Prevalence rates across public skill registries (e.g., 26.1% vulnerability baseline).
4. Defense Frameworks: Sandbox isolation, input sanitization, and dual-LLM evaluation patterns.

### SOURCE CONSTRAINTS & PROVENANCE
• Primary Targets: arXiv preprints, OWASP Agentic Security guides, NIST SP 800-115, CVE databases.
• Exclusions: General vendor marketing material.

### DESIRED REPORT FORMAT
• Threat Taxonomy Summary
• Vulnerability Comparison Matrix
• Remediation Playbook
• References & Provenance List

### CITATION & FACTUAL DISCIPLINE
• Cite specific paper titles, page numbers, or CVE IDs for every threat claim.
```
